Deliberately separated

Collection continues even when the UI is unavailable.

The Agent owns schedules and talks directly to brokers and Elasticsearch. The API never sits in the telemetry ingestion path, and the browser never connects to brokers or storage.

Deploy your way

Start with prebuilt artifacts.

Prepare Elasticsearch, install API and Web, configure read only broker access, and install the Agent last. Verify every release artifact with its SHA256 checksum.

3Independent components
3Supported install models
0Write endpoints in the API
Install in sequence on Linux
# 1. Prepare secured Elasticsearch
# 2. Install and verify MQDeck API
sudo ./mqdeck-api-1.0.7-linux-amd64/install.sh
curl --fail http://127.0.0.1:8080/healthz

# 3. Install Web with Node.js 20.20+
node --version
sudo ./mqdeck-web-1.0.7-linux-amd64/install.sh

# 4. Install and enable Agent last
sudo ./mqdeck-agent-1.0.7-linux-amd64/install.sh
Install API before Agent on Windows
$Version = "1.0.7"
# 1. Install API and verify health
.\install-api-service.ps1
Invoke-RestMethod http://127.0.0.1:8080/healthz

# 2. Configure broker access
# 3. Install Agent last
.\install-agent-service.ps1
Install API and Web with Helm
helm upgrade --install mqdeck \
  oci://ghcr.io/mqdeck/charts/mqdeck \
  --version 1.0.7 \
  --namespace mqdeck --create-namespace \
  --set global.elasticsearch.url=https://elastic.example.com:9200
